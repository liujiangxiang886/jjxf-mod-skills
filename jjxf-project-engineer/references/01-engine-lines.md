# 01 · 引擎线与版本（4.6 / 4.7）

> 出处：内部完整版 §2.5 导出与打包、§5.1 引擎线划分。这是作者问得最多、也最容易搞错的一块。

## 一句话结论

**4.6 与 4.7 是两条完全独立的线，跨线是硬拒绝**——不是版本号差异，是三件实打实不一样的东西：
本体 pck（条目/大小/内容）、引擎（4.6 vs 4.7.2，pack v3 读不了 v4）、代码层（同名脚本整段重写）。

## 双线对照表

| 维度 | 4.6 线 | 4.7 线 |
|---|---|---|
| 定位 | 1.45 原版 | 1.45 剧情版（社区补完剧情） |
| Godot | 4.6.stable（editor，171.9 MB） | 4.7.2.stable（template，109.3 MB） |
| pack 版本 | **v3** | **v4** |
| 基线 ID | `jjxf.v1.45`（别名 v1.45 / 1.45） | `jjxf.v4.7`（别名 v4.7 / 4.7） |
| 本体指纹 | — | **380,259 条目 / 3,066,540,271 B** |
| 随包源码 | sources-4.6.zip，109 个 .gd | sources-4.7.zip，138 个 .gd |
| 安装产物 | overlay-46.pck + manifest-46.v2.json | overlay-47.pck + manifest-47.v2.json |
| 已适配扩展 | 27 个 | 21 个 |
| `--main-pack` | 可以传 | **不能传**（template 关了路径覆盖，报 `compiled without support for path overrides`），靠同名 .pck 自动配对 |

代码层差异举例：`scripts/hud.gd` 4.6 是 18,011 B，4.7 是 32,067 B，`func _ready()` 函数体完全不同。

## 跨线兼容规则

- 4.6 的包装进 4.7：`service.install(target_line=…)` **直接失败**，不会"试着装装看"。
- 一份 zip 想支持两线：放两份清单 + 共用载荷：
  ```
  me.my_ext-1.2.0.zip
  ├─ manifest-46.v2.json
  ├─ manifest-47.v2.json
  └─ payload/
  ```
- 覆盖层、清单副本、启用位、卸载、插桩缓存**全部按线独立**：在 4.6 停用不影响 4.7。
- 补丁跨线程度：`method_hooks` 基本可复用；`data_patches` 要逐条核对（4.7 新增大量字段）；
  `text_patches` **必须按 4.7 源码重算**（锚点会变）。
- 第三条路"自定义线"（custom_baselines + line.json）：1.7 只做到 **probe-only**（可登记、可预检，
  插桩层未接入），**不要对作者承诺"什么改版都能挂"**。

## 剧情层替换（4.7 特有）

- 剧情层是 4.7 的"第一原文"，整片覆盖后所有锚点全变。
- **先停用该线扩展再换层**，然后按新剧情源码重算锚点、发新版本。
- 否则旧 mod 失效，甚至进游戏黑屏。

## 本体指纹闸门（为什么必须标准本体）

启动器按**内容自证身份**（条目数 + 大小 + 指纹），不采信描述里的版本声明。
- 标准 4.7 = 380,259 条目；测试机出现过 379,926 条目的 Demo 包，**不是同一份，会被拦**。
- 换标准本体，或让对方在设置里指向与该本体匹配的反解工程。
- **非标准本体的门不要撬**：指纹拦下意味着"随包源码不再可信"，放宽等于让所有锚点盲打。

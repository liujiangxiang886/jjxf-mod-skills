# 04 · 作者高频问题 FAQ

> 出处：内部完整版 §5.3 典型作者问题（8 问）、§六 典型任务问答（10 问）。都是真实出现过的，按作者提问口吻组织。

## 一、MOD 作者 8 问（真实批量适配中总结）

**Q1：我的 4.6 mod 能直接装到 4.7 吗？**
不能，跨线硬拒绝。`method_hooks` 基本可复用，`data_patches` 要逐条核对（4.7 新增大量字段），
`text_patches` **必须按 4.7 源码重算**。

**Q2：`check` 全过了，为什么导入还是被剔除？**
四道关卡只过了第一道：check → seal → 安装闸门 → 挂载冒烟。最常见是 `verify.absent`（没签封）
和 `conflict.location`（两个包改同一处）。

**Q3：锚点明明在文件里，为什么 0 命中？**
九成是**换行符**：锚点带 CRLF、源码是 LF（22 个社区包里 7 条补丁栽在这）。
其次是锚点不唯一（用 `scope` 限定），或拿了 4.6 的锚点套 4.7。

**Q4：`sources.sha256` 到底填什么？**
填 `sources-4.7.zip` **文件本身**的 sha256，不是本体 pck 指纹。手抄必错，
用 `jjm_pack.py manifest --line 4.7` 生成。

**Q5：装完显示"待插桩"，是失败了吗？**
正常流程。插桩发生在启动时，进游戏稳定 5 秒才翻"已就绪"。一直不翻才看日志哪些脚本没 apply。

**Q6：两个包改同一处 / 挂同一个方法怎么办？**
位置冲突先用 `jjm_pack.py check A.zip --pair B.zip` 算；钩子共存看三档判定
（safe / 需人工 / unknown），写 `result` 一律"读—改—写"，不许整份替换。

**Q7：剧情更新后旧 mod 失效、甚至进游戏黑屏？**
剧情层是 4.7 的"第一原文"，整片覆盖后锚点全变。**先停用该线扩展再换层**，
然后按新剧情源码重算锚点、发新版本。

**Q8：我这儿能装，别人那儿装不上？**
对方本体不是标准 4.7（例如 379,926 条目的 Demo 包），指纹闸门会拦。
换标准本体，或让对方指向与该本体匹配的反解工程。

## 二、现象类问题（10 问，排障思路）

| 现象 | 排查路径 |
|---|---|
| 装完显示"已安装"，进游戏没变化 | "安装成功"≠"生效"。看状态是待插桩还是已就绪 → 日志有没有插桩/合并层跳过 → 钩子目标脚本在本线源码是否存在（hook.method_missing 是 error）→ 源码指纹是否不符导致整层跳过 |
| 4.6 mod 装到 4.6 报锚点 0 命中 | 历史 bug：取源码时无条件读 sources.reversed_project（指向 4.7），4.6 一直拿 4.7 源码比锚点。现按 runtime_sources → project.godot 的 config/features 校验归属 |
| 4.7 扩展全报源码哈希不符 | 随包源码包与本体不匹配。核对 sources-4.7.json 的 sha256 是否=zip 文件本身哈希；确认本体标准 4.7 |
| 8GB 机器选完角色进图卡死十几秒 | 4.7 常驻 6.2GB、装扩展约 7GB，是数据量（252 万动画帧）不是泄漏。四条一起做：贴图缓存 384→64MiB、限帧 60、内存预检、页面文件 16GB+。**别承诺降到 3GB** |
| 启动器昨天能开今天双击没反应 | 配置损坏 + windowed exe 无 stderr。看 config/launcher.json.corrupt-* 留档、logs/ 里"配置无法解析已重置" |
| 导入 mod 时能不能先启动游戏 | 不能也点不动。导入中覆盖层正在写，且运行进程握着 overlay 句柄，改写不生效。整批装完自动恢复，21 包合集约 1 分钟 |
| 完全校验导入要七八分钟正常吗 | 老版本正常（每成员各启一次引擎，21×21.5s）。新版改组合校验实测 62 秒。仍慢就查日志是否重复冒烟 |
| 窗口显示不全按钮被切 | 1366×768 + 150% 缩放可用区仅 911×512，旧下限 1060×600。现下限 940×560 并消除四处撑宽源 |
| 同时装 4.6 和 4.7 会互相污染吗 | 不会，分线隔离是硬约束：覆盖层、启用位、卸载、存档全分线。跨线安装直接拒绝 |
| 自己改了本体（换 pck/打画质补丁）还能用吗 | 能启动但 mod 会被源码闸门拦。自定义版本只启动不挂 mod；想挂 mod 需交付反解源码基线走 custom-baseline 验收 |

## 三、避坑 6 条（作者最容易踩）

1. **一条线一份包**。别做"一份通吃两线"的梦；要通吃就两份清单、payload 共用。
2. **`sources` 是"我的锚点按哪份源码算的"声明**，不是可选装饰。写错比不写更糟：锚点照样命中，
   改的却是另一个函数，表现为"装上了、功能不对"。
3. **`text_patches` 不能跨线复制**。4.7 的 hud.gd 比 4.6 大一倍，_ready() 完全不同。
4. **锚点先过换行符这一关**。CRLF/LF 不一致就是 0 命中，而报错只说"未命中"不说是换行。
5. **`skip_original` 会吞掉同点后续回调**。想叠加就老老实实读—改—写；想独占才用它，并写进文档。
6. **非标准本体的门不要撬**。指纹拦下意味着随包源码不再可信，放宽等于让所有锚点盲打。

> 易误判：纯覆盖层包没有 `scripts.entry` 是正常的。4.7 合集 21 个成员只有 12 个带入口，
> 其余只做资源/数据覆盖，组合校验报 warnings 不是失败。

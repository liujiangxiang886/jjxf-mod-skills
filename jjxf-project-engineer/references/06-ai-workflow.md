# 06 · AI 辅助研发工作流（专家方法论）

> 出处：内部完整版 §四 AI 辅助研发工作流、§八 约束与偏好。这份是"怎么用 AI 把这个项目做出来"的方法论，
> 让专家不仅知道项目事实，还能指导作者/版本维护者用 AI 高效研发。

## 一句话结论

**人给目标和边界，AI 负责"读代码 → 量数据 → 改 → 测 → 出包"，人负责验收"真的能玩、存档没坏、包能发"。**
项目 46,847 行启动器 + 18,637 行测试，19 天，单人 + 单智能体完成。

## 工具清单

| 环节 | 工具 |
|---|---|
| 需求/设计/代码/排错/测试/文档 | WorkBuddy 智能体（Agent 模式，可读写文件、跑命令、跑测试、调 PyInstaller） |
| 代码执行 | 本地 Python 3.13 venv（`_build_tools/venv`）——主环境没有 PySide6/PyInstaller |
| 测试 | pytest（790 用例 / 88.6s，含真引擎用例） |
| 打包 | PyInstaller 6.12.0 |
| 逆向辅助 | Godot --headless、自建 dump_pck.py / diff_packs.py |
| 人工把关 | 实机启动、存档安全、发布包验收 |

**没用到**：多智能体编排、云 IDE、自动 PR review。单人 + 单智能体，上下文连续，但所有验证须自己设计。

## 完整流程（真实 8 步）

1. 用户一句话提需求（给不可改写的成品文案 + 范围 + 追问方向）
2. 定位：不猜，先读代码确认判定来源
3. 先量后改：隔离根跑真实数据拿数字（如 21×21.5s≈7.5min、deepcopy 11.5s）
4. 改代码
5. 补测试（含"队列抛异常时按钮能复位"这类边界）
6. 全量回归（790 passed + 退出码 0）
7. 实盘复测（隔离根重跑，21/21 成功 + 62.1s + 真实存档 mtime 零变化）
8. 出包 + 文档 + 写当日记忆

## 有效 Prompt 模板（原文，真实用过）

| 模板 | 为什么有效 |
|---|---|
| 指定文案 + 范围 + 追问根因："导入mod前提示：这可能需要一些时间…然后查一下完全校验为什么导入时间久，能不能优化？" | 给不可改写文案（省往返）+ 范围 + 追问方向，AI 会先量数据而非直接改 |
| 用"现象+日期"代替版本号："最新的包是1.5吧？我看日期不是今天的，重新打包一下" | 让 AI 去比对 exe 哈希与文件时间，发现混合构建 |
| 明确否定一种做法："其实不用截图给我看了，只要联机功能完成了就不用截图" | 直接砍一类输出，验收改用命令/日志/哈希 |
| 约束资源位置："python不要装在c盘，装D盘建临时工作区，方便后续清理" | 给原则+落地方式，所有工具链统一归宿 |
| 纠正测试方法："游戏自带角色创建，不要套用其他角色" | 把"测试数据必须新建"定为规则，保护真实存档 |
| 结构化缺陷单："现象/报错原文 → 根因 → 解决方案 → 防范措施" | 四段缺一不可；没防范措施的修复过两周会复发 |

## 能力边界（AI 强/中/弱）

| 环节 | 表现 |
|---|---|
| 读大型代码库定位调用链、写测试、批量机械改造 | 强 |
| 性能归因、逆向/二进制格式 | 中——能量出数字，但"该不该保留逐包冒烟"是产品判断；pck/offset 需人给事实 |
| 实机体验判断 | 弱——"进图卡不卡"必须人跑 |
| 存档/数据安全、发布决策 | 必须人把关。2026-10-25 出过事故：override.cfg 用带 BOM 写法 → Godot 读不进 → 用了默认存档 → 真实角色职业被改。规则：写 override.cfg 只能用 bash printf，跑完核对真实存档 mtime |

## 验证四层（缺一层就会漏）

| 层 | 通过标准 |
|---|---|
| L1 单元/集成 | 全绿 + 退出码 0 + config 哈希不变 + du builds 不增长 |
| L2 真引擎冒烟 | ok=True、mounted 含预期包、smoke.nodes≥3 |
| L3 隔离根实盘 | 21 包全装成功、耗时达标、**真实存档 mtime 零变化** |
| L4 发布包解包校验 | exe 哈希、BUILD_ID、sources json 与 zip 哈希一致、extensions.json 空、packs 空、无 D:\ 路径 |

**验收不看截图**：所有结论用命令输出 + 哈希 + 文件时间证明，截图无法证明"跑的是新包"。

## 约束与偏好（专家必须遵守）

- 不碰系统盘/用户目录；依赖/缓存/构建全在 D 盘项目内；临时东西能整删
- 跑游戏前隔离存档：EXE 目录放 override.cfg（use_custom_user_dir=true + custom_user_dir_name）
- 写 override.cfg **只能用 bash printf**，不能 PowerShell Set-Content UTF8（带 BOM）
- 注释解释"为什么"不解释"做什么"；易错点写 docstring 带日期与现象
- 单一事实来源：命令拼装只在 runner.build_command，版本号只在 build_release_zip
- 失败要可解释：每个拒装分支都要有 error code，不出现"安装失败"这种无信息文案
- 沟通：结论先行、不要截图、要实测、汇报含风险与未完成项、中文文档保留英文术语

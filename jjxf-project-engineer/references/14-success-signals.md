# 14 · 成功信号 vs 失败信号（怎么算过了）

> 出处：交付包《04-常见问题FAQ/成功与失败信号对照.md》（171 行）。
> 全部为代码里的字符串常量，不是转述。用途：回答四阶段"怎么算过了"，给可直接 grep 的原文。
> 排障优先读**报告文件**（`mod_report.json`/`mount_report.json`），日志会截断滚动。

## 〇、没有 per-hook 的"成功日志"

钩子注册成功时 `hook_runtime.register()` **静默返回 true**，只有失败才 `printerr`。
判断"钩子生效"靠三个侧面证据：

| 证据 | 位置 | 原文 |
|---|---|---|
| 插桩点已声明 | 启动日志 | `[Hook] 已声明插桩点 {N} 个` |
| 钩子数非零 | `mod_report.json` | `"hooks": {N}` |
| 状态翻转 | 界面 + 日志 | `{line} 线 {n} 个扩展转为已就绪（钩子插桩成功）。` |

**只看到第一条不算成功**——声明了插桩点、一个回调都没注册上，正是"装上没反应"的静默形态。

## 一、四层信号总表

| 阶段 | 成功信号（原文） | 失败信号（原文） |
|---|---|---|
| 打包静态检查 | `结果：错误 0，提示 N，通过` / `SPEC-OK 符合 1.7 打包规范` | `[错误] MAN-../PATCH-../HOOK-..` → `结果：错误 N` |
| 准入预检 | `开发者校验结论：ADMITTED（可发）` | `REJECTED（禁止发布）` |
| 真实本体试装 | `[OK  ] <id>  v1.0.0  补丁 2/2  覆盖 0 命中 / 1 新增` | `[部分]` / `[不兼容]` + `- 原因` 行 |
| 安装 | `[100%] 已安装` + 注册表 `verified: true` | `扩展装上后游戏无法正常启动，已自动撤销。` |
| 挂载冒烟 | `冒烟通过（{N} 节点，{S} 秒）` | `冒烟未通过：退出码 X…节点数 3 < 4；挂载报告 ok=false` |
| mod 装载 | `[ModHost] 已装载扩展：<id>` | `[ModHost] 扩展失败[<id>]：<原因>` |
| 钩子注册 | `[Hook] 已声明插桩点 N 个`（仅证明点存在） | `[Hook] 插桩点不存在：scripts/x.gd::m (after)` |
| 状态翻转 | `{line} 线 {n} 个扩展转为已就绪（钩子插桩成功）。` | 一直停在"待插桩" |
| 秒退兜底 | `本次启动正常，已恢复上次被临时停用的扩展` | 3 秒内非零退出 → 自动停用可疑包并重启 |

## 二、扩展页 8 列与 6 种状态

表头（8 列）：`名称 | 作者 | 版本 | 引擎线 | 状态 | 条目 | 安装时间 | 操作`

| 状态文字 | 含义 | 判定条件 |
|---|---|---|
| `已就绪` | 钩子已插桩、扩展已生效 | 注册表 `status == "ready"` |
| `待插桩` | 用了方法钩子但还没启动过游戏 | `status == "needs_hooks"` |
| `已停用` | 玩家手动关掉 | 该线 `enabled == false` |
| `已剔除` | 被准入闸门拦下，不参与挂载 | `ext_id in view.dropped_set` |
| `不在此线` | 装在别的线 | 该线 `lines` 里没有这个 id |
| `已启用` | 没有钩子的普通包（兜底文案） | `STATUS_TEXT` 查不到时 |

"待插桩"**不是故障**，界面 tooltip 原文：
```
待插桩：这个扩展要用方法钩子，插桩在启动游戏时进行。
首次导入显示「待插桩」属正常现象；启动一次游戏后会变成「已就绪」，
即表示钩子已成功注册、扩展已生效。如果启动之后仍然是待插桩，再看启动日志里的插桩告警。
```

## 三、"稳定 5 秒"有代码依据

| 常量 | 值 | 为什么 |
|---|---|---|
| `READY_AFTER_SECONDS` | `5.0`（`main_window.py:2252`） | 必须**晚于**秒退判定窗口 3 秒——脚本解析失败会在 autoload 阶段秒退，那时钩子没真正加载，标就绪等于骗人 |
| `OBSERVE_SECONDS` | 3 秒（`autofallback.py`） | "3 秒内退出 + 非手动 + 返回码非 0"三条同时成立才算启动失败 |

**不同机器口径一致**：判的是时间，不是帧数或内存。但它只证明"进程活了 5 秒"，
**不等于"玩法正常"**——玩法要人进去点。5 秒内正常退出也会补写回，避免定时器没触发一直停在待插桩。

## 四、机器可读的三份报告（优先读这些）

### `mod_report.json`（ModHost 写，与 `mods.json` 同目录）
| 字段 | 判读 |
|---|---|
| `ok` | `true` 才算全部装载成功 |
| `loaded[]` | 真装起来的 id，少一个就是没装 |
| `failed[]` | `[{id,error}]`：`入口不存在`/`入口加载失败（脚本解析错误？）`/`入口不是 Node`/`入口没有 install()` |
| `warnings[]` | 装上但部分功能未生效：`install() 返回 false（部分功能可能未生效）` |
| `violations[]` | 越界访问被拦（扩展间互相读写没声明 `peer_access`） |
| `hook_writes[]` | 同点后者覆盖前者的记账，最多前 3 次派发 |
| `hooks` | 注册回调总数；**0 且声明了插桩点 = 全是死代码** |
| `game_events[]` | 真订上的 `game.*` 信号（诊断"说订上实际没订"） |
| `ready_state` / `engine` | 就绪探测 / 引擎版本对线 |

### `mount_report.json`（底座写）
`ok` / `mounted[]` / `errors[]`。冒烟判定直接读它：`if not mount.get("ok")` → `挂载报告 ok=false`。

### 日志
`logs/` 下按阶段 grep 上表原文；冻结版 CLI 输出在 `logs/cli-<时间>.log`。

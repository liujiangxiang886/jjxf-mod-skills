# WF-1 · 从零开发新内容（教学向）

> 目标：带一个没接触过的用户，从"我想做个 MOD"走到"我有一份合规的内容目录，可以进 WF-2 打包"。
> 基准：机甲旋风单机版启动器引擎。**先按 WORKFLOWS.md 的硬边界澄清能力范围，再开始。**

## 进入条件与起点确认

进入本流前，先确认三件事（用户答不上来就一步步问，不默认）：

1. **目标引擎线**：4.6 / 4.7 / 自定义基线？——决定源码、锚点、工具参数。
2. **改动类型**：数据补丁（`data_patches`）/ 文本补丁（`text_patches`，4.7 剧情文本）/
   资源覆盖（files，贴图音效）/ 钩子脚本（`method_hooks`）？
3. **已知边界**：用户想"做全新角色/武器"时，先讲清本项目 4.7 只有 `.gdc`、
   不支持自由新建角色，只能数据 / 覆盖层改（出处：`00-project-profile.md` §谁能改什么）。

> 讲清边界不是劝退，是让用户选对实现路径：多数"新武器/新外观"诉求，用**数据补丁 + 资源覆盖**就能达成。

---

## 第 1 步 · 定最小工具链，别装多余的东西

**【目标】** 让用户用最少工具开工，避免卡在环境上。

**【你要做的】** 告诉他需要的只有：
- 该线**标准本体**（4.7 = 380,259 条目那份；非标准会被指纹拦）
- Python 3.9+（`jjm_pack.py` 只用标准库，无需 pip）
- `tools/jjm_pack.py`（单文件）
- 该线 `baseline/sources-<line>.zip`（算 sources.sha256 用，发布版启动器自带）

**不需要**：Godot 编辑器（除非自己做 .tscn/.tres）、反解工程、编译引擎、管理员权限。

**【怎么算过了】** 用户确认 Python 能跑 `python --version ≥3.9`，且能找到 `jjm_pack.py` 和标准本体。

**【下一步】** 进入第 2 步，照最小样例搭骨架。
**【卡住了】** 找不到标准本体 → 指向 `04-author-faq.md` Q8（Demo 包 379,926 条目会被拦）。
**【出处】** `references/02-mod-toolchain.md` §工具清单（三档）

---

## 第 2 步 · 照最小样例搭包骨架

**【目标】** 得到一个能被 `check` 识别的最小合规包。

**【你要做的】** 让用户照 `examples/me.hello_world-1.0.0.zip` 解压后的结构建目录：

```
me.my_ext-1.0.0.zip（打包后）
├─ extension.json          ← 必须在根目录，schema 4
└─ payload/
    └─ data/items.json     ← 换成用户自己的内容
```

`extension.json` 至少写 `schema` / `id` / `name` / `version`。
**用了 `text_patches` 或 `method_hooks` 就必须写 `sources` 三字段**
（name / sha256 / line）——sha256 是 `sources-4.7.zip` **文件本身**的哈希，
手抄必错，用 `jjm_pack.py manifest --line 4.7` 生成。

**【怎么算过了】** 目录结构如上，`extension.json` 能被解析。

**【下一步】** 进入第 3 步，填真正的内容。
**【卡住了】** 不知道 sources.sha256 填什么 → `04-author-faq.md` Q4；
想照抄一个真实包 → 直接用 `examples/me.hello_world-1.0.0.zip` 拆开看。
**【出处】** `references/02-mod-toolchain.md` §最小可用产物；`examples/me.hello_world-1.0.0.zip`

## 第 3 步 · 按改动类型填内容（核心教学步）

**【目标】** 把用户的诉求翻译成正确的补丁类型 + 正确的写法。

**【你要做的】** 按第 0 步确认的改动类型，分路径教学：

### a. 数据补丁（新增武器/道具/数值——最常见）
- 在 `payload/data/` 下按游戏的数据表结构加条目。
- 讲清"数据定义 / 视觉表现 / 行为逻辑 / 接入方式"四部分（出处：`10-general-mod-dev.md` §二），
  让用户明白一个武器通常 = 一条数据 + 一个资源引用，不是写脚本。

### b. 资源覆盖（换贴图/音效/外观）
- 文件放 `payload/` 对应路径，走 `files` 覆盖。
- 提醒：用 files 覆盖基线资源会自动写自指 remap，报 `files.override_baseline` 是 warn 不是 error
  （出处：`03-error-codes.md`）。

### c. 文本补丁 / 剧情文本（4.7 剧情扩展）
- **必须按 4.7 源码重算锚点**，不能拿 4.6 的或跨线复制（`04-author-faq.md` Q1、避坑 3）。
- 锚点 0 命中九成是**换行符**：锚点带 CRLF、源码是 LF。先过这一关（Q3、避坑 4）。
- 锚点不唯一用 `scope` 限定。

### d. 钩子脚本（method_hooks——最易出事）
- `result` 一律"读—改—写"，**不许整份替换**；`skip_original` 会吞掉同点后续回调，只在想独占时用（避坑 5）。
- 先讲清本项目能力边界：4.7 本体源码不可改，钩子靠插桩层。

**【怎么算过了】** 用户有一份填好内容的目录，能说出自己用了哪些补丁类型、sources 是否填对。

**【下一步】** 进入第 4 步，做第一次合规自检。
**【卡住了】** 用户其实是想"做全新角色"（项目不支持）→ 回到进入条件的能力边界，
引导改成数据/覆盖层可实现的目标；不要硬教做不到的路径。
**【出处】** `references/10-general-mod-dev.md` §二/§三；`references/04-author-faq.md` §避坑

---

## 第 4 步 · 第一次合规自检（check）

**【目标】** 在打包前先让工具判一遍合不合规。

**【你要做的】** 让用户跑：

```bash
python tools/jjm_pack.py check ./my_mod --line 4.7
```

（注意 `--line` 要与目标线一致；一条线一份包。）

**【怎么算过了】** 退出码 `0`（**error 数为 0**，warn 不影响退出码）。
文本模式看最后一行"结果"；JSON 模式（`--json`）看 `ok` 字段（唯一判据）。

**【下一步】** 0 error → 进入 WF-2 做完整打包验证与签封。
**【卡住了】** 有 error → 把错误码原样记下，进 WF-5 按码定位；
常见：锚点 0 命中（换行符）、sources.sha256 不符、缺字段（出处：`03-error-codes.md` §一）。
**【出处】** `references/07-tool-usage.md` §退出码/§报告怎么读

---

## 本流完成标准

用户产出一份 `check` 0 error 的内容目录，并能说清：目标线、补丁类型、sources 依据。
→ 交接给 **WF-2**（标准线）或 **WF-3**（自定义基线）做打包验证与签封。

# WF-4 · 安装与冒烟跑通

> 目标：把签封包装进启动器，并用**可观测的信号**确认真的生效——这是"跑通"的验收终点。
> 出处：`references/02-mod-toolchain.md` §安装与状态；`WORKFLOWS.md` §五跑通的定义。
>
> 核心提醒：**"安装成功" ≠ "生效"**。必须走完状态机 + 冒烟，四道关卡全过才算跑通。

---

## 第 1 步 · 正确安装（用对命令）

**【目标】** 用对安装命令，避免合包被逐文件安装器拒绝。

**【你要做的】**
- **合包**（一个 zip 含多个扩展）→ 用启动器「游戏库」的合包安装（`cli ext --install`）。
- `cli mods install` 是**逐文件直装**，喂合包会报"扩展包的信息不完整"。
- 安装期间**不能启动游戏、启动按钮置灰**：运行中的进程握着 `overlay-*.pck` 句柄，
  此时改写不生效。整批装完自动恢复，21 包合集约 1 分钟。

**【怎么算过了】** 安装完成，启动按钮恢复可用。
**【下一步】** 第 2 步，看状态机。
**【卡住了】** 报"信息不完整" → 用错安装命令，换合包安装；卡在导入中 → 等整批装完，不要中途启动。
**【出处】** `references/02-mod-toolchain.md` §安装与状态；`04-author-faq.md` 现象类"导入 mod 时能不能先启动"

---

## 第 2 步 · 看状态机（待插桩 → 已就绪）

**【目标】** 用扩展页状态判断是否进入挂载阶段。

**【你要做的】** 让用户看扩展页状态列（出处：`references/14-success-signals.md`）：
- 表头 8 列：`名称 | 作者 | 版本 | 引擎线 | 状态 | 条目 | 安装时间 | 操作`。
- 状态列只有 6 种：`已就绪` / `待插桩` / `已停用` / `已剔除` / `不在此线` / `已启用`。
- `待插桩 = needs_hooks` → **正常中间态**，不是故障。插桩发生在启动时，
  **进游戏稳定 5 秒才翻 `已就绪 = ready`**（`READY_AFTER_SECONDS = 5.0`，且须晚于 3 秒秒退窗口）。
- 一直停在待插桩不翻 → 看日志插桩告警。

**⚠️ 没有 per-hook 的"成功日志"**（很多人问，别答错）：钩子注册成功时静默返回 `true`，
只有失败才 `printerr`。判断"钩子生效"要靠三个侧面证据：
①启动日志 `[Hook] 已声明插桩点 N 个`（仅证明点存在）；
②`mod_report.json` 的 `"hooks": N`（非零）；
③状态翻 `{line} 线 {n} 个扩展转为已就绪（钩子插桩成功）。`
**只看到①不算成功**——声明了插桩点、一个回调都没注册上，正是"装上没反应"的静默形态。

**【怎么算过了】** 状态翻到 `已就绪`（稳 5 秒后仍保持），且 mod_report 的 hooks 非零。
**【下一步】** 第 3 步，启动游戏冒烟验证。
**【卡住了】** 一直待插桩 → WF-5（钩子目标脚本是否存在、`hook.method_missing`、源码指纹）；
典型失败原文 `[Hook] 插桩点不存在：scripts/x.gd::m (after)`。
纯覆盖层包没有 `scripts.entry` 是**正常的**（4.7 合集 21 个成员只有 12 个带入口），别误判。
**【出处】** `references/14-success-signals.md` §〇/§二/§三；`references/02-mod-toolchain.md` §安装与状态

---

## 第 3 步 · 启动游戏冒烟（最终确认生效）

**【目标】** 确认 mod 内容在游戏里真的体现，不只是状态显示 ready。

**【你要做的】** 让用户启动一次游戏，对照自己的改动验证：
- 数据补丁 → 进游戏看新增武器/道具/数值是否出现。
- 文本补丁 → 看剧情文本是否替换。
- 资源覆盖 → 看贴图/音效是否变化。
- 同时确认游戏稳定运行（不黑屏、不卡死）。

**【怎么算过了】** 改动可在游戏内观察到，且游戏稳定。

**【下一步】** 四关全过 → **跑通完成**。可引导用户按 LEARNING.md 沉淀本次经验。
**【卡住了】**
- 装了没变化 → WF-5：状态是待插桩还是已就绪 → 日志有无插桩/合并层跳过 → 钩子目标脚本是否存在 → 源码指纹是否不符导致整层跳过。
- 换剧情层后黑屏 → 先停用该线扩展再换层，按新剧情源码重算锚点、发新版本（Q7）。
- 选完角色进图卡死十几秒 → 4.7 数据量大（252 万动画帧、常驻 6.2GB），是数据量不是泄漏；
  四条一起做：贴图缓存 384→64MiB、限帧 60、内存预检、页面文件 16GB+。
  **别承诺降到 3GB**（出处：`04-author-faq.md` 现象类）。
**【出处】** `references/04-author-faq.md` §二现象类；`WORKFLOWS.md` §五

---

## 跑通验收清单（四关全过）

- [ ] ① `check` 0 error（WF-1/WF-2）
- [ ] ② `seal` 已签封、`verification.json` 与代码层指纹匹配（WF-2）
- [ ] ③ 安装闸门通过，无 `conflict.location`（WF-4 第 1 步）
- [ ] ④ 挂载冒烟：状态翻 `ready`、游戏内可见改动、游戏稳定（WF-4 第 2-3 步）

四关缺一不算跑通。**`check` 全过只是第一关**——这是反复强调的作者最常见误解。

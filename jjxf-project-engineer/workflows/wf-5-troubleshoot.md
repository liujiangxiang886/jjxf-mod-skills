# WF-5 · 排障闭环

> 目标：用户报"装了没生效 / 被剔除 / 0 命中 / 报错码 XXX"时，按统一方法定位，修完回到卡住的那一步重跑。
> 这是所有工作流卡住时的汇流点。取证：`references/03-error-codes.md`、`04-author-faq.md`、`07-tool-usage.md`。

---

## 统一定位顺序（先看阶段，再看剔除，最后才怀疑本体）

出处：`03-error-codes.md` 开头排查顺序。

```
① 看码的阶段 → 打包(PKG/MAN/SRC/HOOK) / 安装(install) / 组合(conflict) / 启动(verify 等)
② 看是不是被"剔除"类：verify.* / conflict.* / gate.* / baseline.*
   ——这类不是包坏了，是"与环境对不上"
③ 最后才怀疑本体与源码
④ 同一条日志多个码 → 先修级别最高的
```

**【你要做的】** 让用户把错误码或日志原文贴出来；没有码就按下面的"现象速查"对号入座。

---

## 一、按错误码定位

**【目标】** 把码 → 触发条件 → 修法 → 出处一一对上。

**【你要做的】** 到 `references/03-error-codes.md` 查该码，给用户四件事：
触发条件、级别（error/warn/剔除）、修法、日志原文关键词。
（完整码表在 `03-error-codes.md` 与知识库《错误码全集.md》。）

**高频码速查**（出处：`03-error-codes.md`、`04-author-faq.md`）：

| 码/现象 | 根因 | 修法 |
|---|---|---|
| `verify.absent` | 没签封 | 跑 `seal` 写 `verification.json` |
| `verify.stale` | 记录与代码层指纹不符 | 按当前版本重新 `seal`（seal 后别再改文件） |
| `baseline.mismatch` / `code_mismatch` / `size_mismatch` | 本体与基线不符 | 换标准本体（基本就是本体不对） |
| `SRC-05`（全线） | 源码 zip 与本体不一致 / json sha256 写错 | 恢复匹配源码包；sha256 改回 zip 哈希 |
| 锚点 `0 命中` | 九成是换行符（锚点 CRLF、源码 LF）；其次锚点不唯一 / 跨线 | 统一换行符；用 `scope` 限定；按本线源码重算 |
| `hook.method_missing` | 钩子目标脚本在本线源码不存在（error） | 换目标或去掉该钩子 |
| `conflict.location` | 两包改同一处 | `check --pair` 算，收窄锚点 / overrides+expect / 二选一 |
| `install.smoke` | 挂载冒烟没过 | 看状态是否翻 ready、日志插桩层是否跳过 |
| `SEAL-03` | 找不到 identity-<线>.json | 补该线代码层指纹 |
| `SEAL-04` | seal 前 check 未通过 | 先 check 0 error 再 seal |

**【怎么算过了】** 用户知道该码的根因与修法，并回到对应工作流步骤重跑后通过。
**【出处】** `references/03-error-codes.md`；`07-tool-usage.md` §退出码/§已知误报

## 二、按现象定位（用户说不清码时）

出处：`04-author-faq.md` §二现象类 10 问。

| 现象 | 定位路径 |
|---|---|
| 装完"已安装"但进游戏没变化 | "安装"≠"生效" → 状态待插桩还是已就绪 → 日志有无插桩/合并层跳过 → 钩子目标脚本是否存在 → 源码指纹是否不符致整层跳过 |
| `check` 全过仍被剔除 | 只过第一关 → 查 `verify.absent` / `conflict.location` |
| 我这儿能装别人装不上 | 对方本体非标准（如 379,926 条目 Demo）→ 指纹闸门拦；换标准本体 |
| 自定义线不挂扩展 | 分档是 `probe-only`，或钩子类被插桩层未接入的硬约束跳过 → 补 `line.json`；钩子类当前不可用 |
| 4.6 包在 4.7 命中 0 处 | 拿了 4.7 源码核 4.6 锚点 → 按线匹配 source_root，读 `project.godot` 的 features 首项 |
| 4.7 扩展全报源码哈希不符 | 随包源码包与本体不匹配 → 核 `sources-4.7.json` 的 sha256 是否 = zip 哈希，确认标准本体 |
| 剧情更新后旧 mod 失效/黑屏 | 剧情层是 4.7"第一原文"，整片覆盖锚点全变 → 先停用扩展再换层，按新源码重算发新版 |
| 启动器双击没反应 | 配置损坏 + windowed exe 无 stderr → 看 `config/launcher.json.corrupt-*` 留档、`logs/` 的"配置无法解析已重置" |
| 验证导入很慢（七八分钟） | 老版本每成员各启一次引擎；新版组合校验实测 62 秒。仍慢查日志是否重复冒烟 |
| 窗口按钮被切 | 1366×768 + 150% 缩放可用区小 → 现下限 940×560 已修 |

**【怎么算过了】** 现象对上号、用户拿到明确修法。
**【下一步】** 修完**回到当时卡住的那一步重跑**（不是从头再来）：
- 打包类问题 → 回 WF-2 对应步骤
- 自定义线问题 → 回 WF-3 对应步骤
- 安装/生效问题 → 回 WF-4 对应步骤
**【卡住了】** 若本文件与知识库都覆盖不了 → 明说"现有资料没有，需向版本作者确认"，
不臆测；并按 LEARNING.md 把这次新问题记为经验条目，供专家下次学习。
**【出处】** `references/04-author-faq.md`；`references/03-error-codes.md`

## 三、排障时的三条红线

1. **非标准本体的门不要撬**：指纹拦下意味着随包源码不再可信，放宽等于让所有锚点盲打（出处：`04-author-faq.md` 避坑 6）。
2. **一条线一份包**：别做"一份通吃两线"；要通吃就两份清单、payload 共用（避坑 1）。
3. **测试前隔离真实存档**：写 `override.cfg` 只能用 bash printf（不能 PowerShell UTF8，会带 BOM）；
   测试角色要新建，不拿已有角色改职业顶替（出处：Agent MD 注意事项 + 用户约定）。

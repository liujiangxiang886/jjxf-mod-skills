# normalize-rules · 分层、去重、冲突与质量门槛

## 一、分层判定（决定条目进哪个知识层）

```
资料讲的是 Godot 引擎通用机制（节点/资源/信号/动画帧/任意游戏）？
  └─ 是 → layer=通用, lines=["通用"] 或具体游戏名
资料讲的是机甲旋风/新起点启动器专属（4.6/4.7、jjm_pack、错误码、剧情层、本体指纹）？
  └─ 是 → layer=项目, lines 填涉及的 4.6 / 4.7
两者都沾 → 拆成两条，别混在一条里。
拿不准 → 标 layer 并在 source 写"分层待确认"，交由用户判断。
```

**硬边界**：机甲旋风 4.7 只有 `.gdc`、不能改源码重编译、不支持自由新建角色；
通用层"加节点写脚本"那套不可套到项目层。导入时若资料混淆两者，拆开并标注。

## 二、去重（导入器自动执行）

- 判重键：`(date, title)` 完全相同，或生成的目标文件名已存在。
- 结果：默认**跳过**重复条目并在报告 `conflicts` 列出；用户加 `--force` 才覆盖。
- 同一清单内部重复：直接判为错误，阻断本次导入（避免自己覆盖自己）。

## 三、冲突处理（推翻旧结论）

若 `supersedes` 非空（新经验证明 references 或旧条目错了）：

1. 条目照常落库，`supersedes` 写明被替换的 `references/xx.md §章节`。
2. **不要**静默改 references——按 `jjxf-project-engineer/LEARNING.md` 通道 C：
   改对应 references + 在改动处标 `[更新于 YYYY-MM-DD：原因]` + 同步 SKILL.md 路由/口径 + 变更记录登记。
3. 若涉及口径（对外版本 V1.5 / 4.7 条目数 380259 / 渲染后端 gl_compatibility+d3d12），
   必须同步主技能的 references/00-project-profile.md 与 SKILL.md"口径统一"节。
4. 重新打包专家包（validate → register → package，并递增 plugin.json version）。

## 四、质量门槛（提炼时对每条自检）

- [ ] 结论先行，一句话说清（`conclusion`）
- [ ] 有出处（`source` + `evidence`：文件章节/日志/命令输出/日期）
- [ ] 有可复核数字或原文（不是"感觉变快了"）
- [ ] 有防范措施（`prevention`）——不只说怎么修，还说怎么防复发
- [ ] 标了 layer 与 lines
- [ ] 若推翻旧结论，填了 `supersedes`
- [ ] 已脱敏（无本机路径/账号/真实存档名/凭据）

缺失的正文段，导入器会写入"（待补充）"并在报告 warnings 提示；
不阻断落库，但应由用户补齐后再确认一次。

## 五、措辞纪律

- 项目层：只用资料里有的事实；数字/命令原样照抄，不换算、不推测。
- 通用层：可结合 Godot 客观 API 补全，但要标"基于 Godot 机制，非本项目专项资料"。
- C 级资料：明确写"待版本作者确认"，不得写成既定事实。
